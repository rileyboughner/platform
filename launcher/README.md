# launcher

The single Android launcher codebase: phone, tablet, and Google TV entry
points in one app, sharing one data layer and the rose-pine design tokens
generated by `../theme/` (Phase 1). This is the Phase 2 skeleton described
in `../docs/architecture.md` — **app list + navigation + theme + stubs
only.** No Jellyfin/Home Assistant integrations, no network code, no auth.

## Project structure

```
launcher/
  settings.gradle.kts        Module list, repositories (google(), mavenCentral())
  build.gradle.kts           Root build file — plugin versions only
  gradle.properties
  gradlew, gradlew.bat       Gradle wrapper scripts (see "Gradle wrapper" below)
  gradle/wrapper/
    gradle-wrapper.properties  Pins Gradle 8.7
  app/
    build.gradle.kts         App module: AGP + Kotlin + Compose + Compose for TV,
                              plus the theme wiring described below
    src/main/
      AndroidManifest.xml    Declares both entry-point activities
      kotlin/dev/rileyboughner/launcher/
        MainActivity.kt        Phone/tablet entry point (HOME + LAUNCHER)
        TvMainActivity.kt       Google TV entry point (LEANBACK_LAUNCHER)
        AppListRepository.kt    PackageManager query — the only data source
        theme/AppTheme.kt        Compose MaterialTheme, sourced from PlatformTheme
        ui/
          AppGridScreen.kt        Phone/tablet app grid
          TvHomeScreen.kt          TV browse-style stub screen
          JellyfinContinueWatchingRow.kt   Stub — deep link only, see below
          HomeAssistantPanel.kt    Stub placeholder panel
          NotificationBadge.kt    Count-only badge
      res/
        values/strings.xml, themes.xml   No color values — see "Theme" below
```

## How to build

**Requires:**
- JDK 17
- Android SDK (compileSdk 34, Build-Tools matching AGP 8.5.2) — set
  `ANDROID_HOME`/`ANDROID_SDK_ROOT` or create `launcher/local.properties`
  with `sdk.dir=/path/to/Android/Sdk`
- Network access on first run, for Gradle to resolve the AndroidX/Compose/
  Compose-for-TV dependencies declared in `app/build.gradle.kts`

```
cd launcher
./gradlew assembleDebug      # phone/tablet + TV code in one APK
./gradlew installDebug       # install to a connected device/emulator via adb
```

### Gradle wrapper

`gradlew` / `gradlew.bat` are included, but **`gradle/wrapper/gradle-wrapper.jar`
is not** — this skeleton was assembled in an environment with no Gradle, JDK,
or Android SDK installed, so there was nothing available to generate or
verify that binary. Before `./gradlew` will run, either:
- run `gradle wrapper` once from any machine that has Gradle installed, from
  inside `launcher/`, which will populate the jar from
  `gradle-wrapper.properties` (pinned to Gradle 8.7), or
- open the project in Android Studio, which bootstraps the wrapper itself.

## Per-form-factor entry points

Both entry points live in the same app and share `AppListRepository`,
the theme, and (once built out) the Jellyfin/Home Assistant data layer.
Only the presentation layer branches by form factor:

- **Phone/tablet — `MainActivity`** (`android.intent.category.HOME` +
  `LAUNCHER`). This is the default-home candidate: after installing the
  APK, set it via Settings → Apps → Default apps → Home app. Shows
  `AppGridScreen` — a grid of installed apps, the Jellyfin stub row, and
  the Home Assistant stub panel.
- **Google TV — `TvMainActivity`** (`android.intent.category.HOME` +
  `LEANBACK_LAUNCHER`). Shown as a candidate "home" on Leanback (Android
  TV / Google TV) devices. Setting it as the actual default home is not
  guaranteed on every OEM build — see the platform proposal, section 3,
  for the known risk with the Google TV purchase. Shows `TvHomeScreen`, a
  minimal D-pad-navigable row — explicitly a stub, not the real TV UI.

## Theme

No color is defined, redefined, or duplicated anywhere in `launcher/`.
Both entry points read colors from the Phase 1 Style Dictionary output in
`../theme/build/android/` (committed, tracked outside `launcher/`):

- **`theme/build/android/Theme.kt`** (`platform.theme.PlatformTheme`,
  a Kotlin `object` of `Color` values) is added directly as an extra
  Kotlin source directory in `app/build.gradle.kts`
  (`kotlin.srcDir(...)`). Kotlin source sets don't require directory
  layout to mirror package name the way Java's does, so this compiles
  straight out of `theme/build/` with no copy.
  `theme/AppTheme.kt` builds the Compose `MaterialTheme` color scheme
  entirely from `PlatformTheme` fields.
- **`theme/build/android/colors.xml`** is an Android `values` resource
  file, but Style Dictionary writes it flat (no `values/` parent
  directory), and AAPT only recognizes resource files inside a qualifier
  directory. `app/build.gradle.kts` registers a `syncThemeColors` Gradle
  task (a plain `Sync`, wired into `preBuild`) that copies just that file
  into a generated `build/generated/rosePineTheme/res/values/colors.xml`
  at build time, and adds that generated directory as an extra `res`
  source dir. The repo never gets a hand-maintained second copy of the
  palette — only a build-time, mechanically-generated one.

If the palette changes, it changes once in `theme/tokens.json`, rebuilds
`theme/build/android/`, and both of the above pick it up automatically.

## What's still a stub

- **`JellyfinContinueWatchingRow`** — static placeholder text and a single
  deep link into the installed Jellyfin app (`org.jellyfin.mobile`) via
  `PackageManager.getLaunchIntentForPackage`. No Jellyfin API client, no
  network calls, no "continue watching" data, no playback code, no
  reimplemented player — per the platform proposal, that's a hard
  boundary, not a shortcut.
- **`HomeAssistantPanel`** — static placeholder text only. No Home
  Assistant REST/WebSocket client, no entities, no auth.
- **`NotificationBadge`** — renders a count only (capped display at
  "99+"). There is no notification content anywhere in this app, and no
  access to the system notification shade — Android launchers don't own
  that, so badge counts are the realistic ceiling here.
- **`TvHomeScreen`** — a single row of app tiles to prove the
  `LEANBACK_LAUNCHER` entry point and the Compose-for-TV dependencies
  wire up; not the real TV browse UI (no rows-of-rows, no Jellyfin/Home
  Assistant panels on TV yet).
- **App icon** — uses the stock `@android:drawable/sym_def_app_icon`
  placeholder; no real app icon/adaptive icon asset has been designed.
- **Gradle wrapper jar** — see "Gradle wrapper" above.

## Build verification actually performed

This environment has no Android SDK, no Gradle, no JDK, and no Kotlin
compiler, and deliberately was not given one — fetching a real Android
SDK means a multi-gigabyte download, which was explicitly out of scope
for producing this skeleton. The environment also lacks `xmllint` and
`python3`. What was actually checked, by hand, with only `grep`/`perl`/`sh`:

- `sh -n gradlew` — shell syntax of the wrapper script is valid.
- Brace/paren balance per `.kt`/`.kts` file (every open `{`/`(` has a
  matching close) — a weak but cheap signal against unclosed blocks.
- Manifest tag balance (`<manifest>`, `<application>`, `<activity>`,
  `<intent-filter>`, etc. all open/close in equal counts) and a read-through
  of the full file.
- Manual review of every Gradle/Kotlin/XML file for import correctness,
  dependency coordinates, and the theme source-dir wiring described above.

**Not done, and not claimed:** no `./gradlew build`, no Kotlin
compilation, no AAPT resource merge, no APK was produced. The
`syncThemeColors` resource-sync approach and the `androidx.tv:tv-*`
Compose-for-TV API usage (`TvLazyRow`, `androidx.tv.material3.*`) are
written from documented APIs but unverified against a real compiler —
first real build is the actual test of both.
